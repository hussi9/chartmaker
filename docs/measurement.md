# ChartGenie cohort 01 measurement

Required event enum/chart-type/count fields reject the whole event when missing or invalid; extra properties are stripped. Consent Mode updates can themselves cause provider requests, so source-level `ga-disable` sequencing is not proof of zero withdrawal pings. Keep the readiness gate off until actual provider payload/withdrawal verification passes.

Consent Mode v2 (October 2026): on clean allowlisted public routes the tag loads with `gtag('consent','default',...)` issued before the script download — `analytics_storage`, `ad_storage`, `ad_user_data` and `ad_personalization` all denied. In that state GA sends cookieless measurement pings only (aggregate session/visit counts, no cookies, no banner). The Privacy choices "allow" issues `gtag('consent','update',{analytics_storage:'granted'})`; ad signals are never upgraded and `allow_google_signals`/`allow_ad_personalization_signals` stay false. An explicit "keep measurement off" choice, or a failed preference write, sets `ga-disable-ID` and stops every send, including cookieless pings. Do Not Track and Global Privacy Control prevent the tag from loading at all. Product events still require the explicit grant; only the sanitized page_view ping flows pre-consent.

All URLs containing any query or fragment are excluded, even on otherwise public routes. A pre-router history observer disables GA before push/replace mutations, then checks current eligibility; popstate, hashchange and cross-tab preference changes also refresh the disable flag without emitting views. Loader referrers are suppressed. Actions during provider loading are dropped, not queued. These intentional exclusions and loading loss must be visible in reporting, not reported as zero activity.

`VITE_GA_MEASUREMENT_READY=true` is a release gate, not a normal default. Do not enable until actual provider payload, Enhanced Measurement/automatic event behavior, and post-load withdrawal proof pass. Vercel page monitoring (`src/lib/browser-monitoring.js`) has its own gate, `VITE_VERCEL_WEB_MEASUREMENT_READY` (off only when explicitly `false`) and, unlike the GA ping path, still requires the explicit visitor grant.

The route/event inventory is `measurement-coverage.json`. Existing route `onEnter` hooks are the sole GA pageview owner. Consent acceptance does not replay pre-consent views or actions. Shared chart routes, account/admin, unknown paths and static privacy notices are excluded. Route patterns are matched against the actual browser route before events are emitted.

Every explicit GA config/event supplies a sanitized origin plus the allowlisted route pattern, fixed title and empty referrer; a global `gtag('set',{page_location:origin+route,page_path:route})` runs so provider-automatic events never inherit a concrete id, query or hash. All action parameters are bounded enums or integer counts. No title/chart data/query/hash/user ID is intentional telemetry. DNT/GPC override optional consent. Disabling measurement sets `ga-disable-ID` and blocks subsequent application sends. Actual Google automatic/session events require separate live proof; source-level sanitation alone is not that proof. Already dispatched requests cannot be recalled.

Evidence: local runtime tests validate consent defaults before the script, the cookieless ping gate, analytics_storage-only opt-in, opt-out/failed-write kill, DNT/GPC skip, route-pattern sanitization and the Arguments-object queue contract. Full build/test evidence belongs in the parent release record. No provider settings, deployment, retention or receipt are claimed verified by this implementation.

Future cohort reuse: retain a product-specific preference key and explicit route/event catalog; map every router route to eligible or intentionally excluded; require secret-canary synthetic payload checks; record deployment revision and UTC test window; keep readiness off if a collector bypasses withdrawal or leaks context. Do not sum GA and Vercel totals.
