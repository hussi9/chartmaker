# GA context and activation gates

The application owns explicit pageviews. `send_page_view:false` prevents the config command's pageview; Enhanced Measurement must remain OFF to avoid a second owner, history-driven pageviews and DOM capture. Provider-setting evidence, not client payload proof, should confirm Enhanced Measurement OFF and the retention window before activation.

Every config, explicit pageview and product event uses an allowlisted canonical public `page_location` (origin + route pattern, never a concrete chart id), a fixed `page_title`, and empty `page_referrer`. No browser document title, raw URL, referrer, query values or hash values are passed. A global `gtag('set',{page_location:origin+route,page_path:route})` runs after config so provider-generated engagement events inherit safe context rather than the previous route or a concrete id. Product events explicitly override context as well.

Consent Mode v2 (October 2026): on clean allowlisted public routes the tag loads with `gtag('consent','default',...)` issued before the script download — `analytics_storage`, `ad_storage`, `ad_user_data` and `ad_personalization` all denied. In that state GA sends cookieless measurement pings only (aggregate session/visit counts, no cookies, no banner). The Privacy choices allow button issues `gtag('consent','update',{analytics_storage:'granted'})`; ad signals are never upgraded and `allow_google_signals`/`allow_ad_personalization_signals` stay false. An explicit "keep measurement off" choice or a failed preference write sets `ga-disable-ID` and stops every send, including cookieless pings. Do Not Track and Global Privacy Control prevent the tag from loading at all. Product events still require the explicit grant; only the sanitized page_view ping flows pre-consent.

GA may generate automatic `user_engagement`, session and lifecycle events even with Enhanced Measurement OFF. The implementation does not treat disabling Enhanced Measurement as proof these events are absent or sanitized. Before activation, inspect actual request payloads for those automatic events after dwell, pagehide, tab switching and SPA navigation using synthetic title/query/hash/referrer canaries. Confirm no raw content/context leaks. If provider automatic behavior cannot satisfy this, leave readiness OFF.

The history observer joins the router. Query-only navigation, hashchange/popstate and cross-tab storage changes all reevaluate the gate, including public route to the same public route with a sensitive query, and removal of that query. Any query/hash, unknown route, account route or share route disables future sends via `ga-disable-ID`. The gateway independently rereads the current URL, preference and privacy signals for each product event. After returning to an eligible context the explicit pageview owner resumes without replaying previous events.

The observer runs after navigation commits. Browser/provider scheduling around navigation, queued requests, automatic engagement and withdrawal therefore remain a live release test, not a guarantee inferred from unit tests. Already-dispatched requests cannot be recalled. Consent withdrawal does not reload, clear editor state or claim deletion of past provider data.

`VITE_GA_MEASUREMENT_READY` gates the GA tag in every environment; it must be exactly `true` in the Vercel production env for cookieless pings to flow (verified set to `true` for production on October 10, 2026 — the sibling SignatureMaker migration previously stored a pasted Doppler ciphertext envelope, which kept its gate closed; ChartGenie's value is the literal string `true`). The Vercel Web Analytics collector (`src/lib/browser-monitoring.js`) is integrated and has its own gate, `VITE_VERCEL_WEB_MEASUREMENT_READY` (off only when explicitly `false`); unlike the GA ping path it still requires the explicit visitor grant. The gtag command queue must push the function's `arguments` object (`window.dataLayer.push(arguments)`), never a rest-parameter array — gtag.js silently drops arrays and sends zero hits.
