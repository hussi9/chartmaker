Deliverable 5

Navigation

Two labelled groups, one bar

Create (Draw · Type · Scan) and Use (Download · Stamp · Animate · PDF) sit as two segmented controls under the header. The active segment is filled with the accent; the inactive group stays reachable, so moving between stages is always one click.

One primary per screen

Create screens have a single primary "Continue to {destination}". Outputs have a single primary export. Everything else (Edit signature, Replace file, Copy) is secondary or ghost. Step numbers and repeated headings are omitted; the segmented control is the only wayfinding.

Inputs vs outputs

Every screen is a two-column workspace: the working canvas or live preview on the left, compact controls on the right, actions pinned to the bottom of the control panel behind a 2px rule.

Supporting pages

Footer links open templated guide/legal pages inside the same shell with one CTA back into the tool. The header and stage bar stay in place.

State preservation

Three drafts

Draw, Type and Scan each own a draft object (strokes/redo stack, text/font/ink/size, photo/threshold/cleaned PNG). Switching method, stage or page never clears them.

Current signature

Set when the user continues from a draft. Editing keeps the same kind; returning to an output re-renders it with the change. Clearing a draft makes the chip fall back to the next draft with content, or to "No signature yet".

Per-output settings

Stamp keeps its graphic, position, scale, opacity, badge and contrast; Animate keeps style, format, background, duration and fps; PDF keeps the file, its parsed metadata, preset and size. Success messages reset when a setting changes so a stale "Saved" never shows.

Intended output

Entering an output without a signature stores that output. The Create screen's primary reads "Continue to PDF" and the hint says the settings are waiting; continuing returns there and clears the intent.

Prototype scope

Canvas drawing, typing, photo clean-up, PNG/SVG download and stamp compositing are real and local. WebM recording and PDF writing are simulated with realistic progress, cancel, failure and success states (the first Animate export fails once to demonstrate recovery; toggle in Tweaks).

Responsive behaviour

Desktop ≥ 761px

Header with brand, signature chip and theme toggle; stage bar with both groups; two-column workspace (fluid canvas, 340px controls). Font grid is three across.

Tablet

Same structure; the stage bar wraps to two rows when both groups don't fit. Controls column keeps its width; canvas shrinks.

Mobile ≤ 760px

Chip drops its text label; the stage bar shows only the active group at full width with 44px targets; a bottom tab bar (Create · Use) switches stages. Workspace stacks: canvas first, controls beneath, actions at the end of the panel. Font grid becomes two across; scan previews stack. Force either layout with the Viewport tweak.

Accessibility

Modernist tokens: 2px accent focus ring, ≥ 3:1 chrome and ≥ 4.5:1 body contrast in both themes, pressed states via aria-pressed, canvas ignores non-primary buttons and uses pointer capture for stylus and touch.

Deliverable 4

Demo scripts

Type → Download → Edit → Download

Type a name, pick a style, Continue to Download, save PNG, Edit signature (lands on Type with the same font), change ink, return via Use · Download.

Draw → Stamp → Edit → Stamp

Draw, Continue, open Stamp, use the sample photo, set corner/scale/badge, Edit signature, add a stroke, Use · Stamp: photo and settings intact.

Scan → Animate → Edit → Animate

Scan a photo, tune Paper removal, Continue, open Animate, export (first attempt fails, retry succeeds), Edit signature, adjust threshold, return.

PDF without a signature

Open Use · PDF on a fresh load: missing-signature panel. Type it, Continue to PDF, land back on PDF.

PDF upload → placement → Edit → return

Choose a PDF, see name/pages/dimensions, pick a preset and size, Edit signature, come back: file and placement retained.
